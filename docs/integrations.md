# Integrations / connectors

Every 3rd-party provider follows the same layered pattern. Take Jira as the example:

| Layer                 | File                                                                    | Responsibility                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider client       | `packages/core/src/lib/jiraManager.ts`                                  | Thin wrapper around the provider's own SDK (`jira.js`, `googleapis`, `dropbox`, `@octokit/*`, `@azure/storage-blob`, `facebook-nodejs-business-sdk`, `@microsoft/microsoft-graph-client`, `ssh2-sftp-client`, `soap`, `twilio`). Owns a `forAuth`/`forCredential`-style cache keyed by the resolved credential so one node reuses the same authenticated client/connection across calls instead of rebuilding it every execution, and (where the provider's tokens actually expire, e.g. Dropbox OAuth2) handles refreshing them.      |
| Runtime logic         | `packages/core/src/server/functionLibraryJira.ts`                       | The compiled/deployed-script counterpart: reads the credential back from env vars (`credentialEnv.ts` conventions, see [auth.md](./auth.md)) instead of the vault, then calls into the same manager.                                                                                                                                                                                                                                                                                                                                   |
| Node definition       | `packages/graph/src/nodes/jira.ts`                                      | Both execution paths for every operation: `execute()` (interpreter path — resolves the credential from the vault via `ctx.getCredential` and calls the manager directly) and `compileExecute()` (compiled path — calls the matching `functionLibrary<Provider>.ts` export). Both run only server-side (see [architecture.md](./architecture.md)'s "Where node code actually runs"); the file is still imported by client bundles for the node-creation menu, so keep any Node-only code inside function bodies, never at module scope. |
| Struct/enum pin types | `packages/graph/src/structs/jira.ts`, `packages/graph/src/enum/jira.ts` | Typed pin shapes surfaced in the editor for this provider's data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

Current providers: Dropbox, GitHub, Google (Admin/Calendar/Docs/Drive/Gmail/Sheets/Auth), Jira, Facebook, Azure Storage, Microsoft 365, AWS DynamoDB, MongoDB, Slack, Stripe, Salesforce, Workday, Twilio, SMTP, SAP (OData/Gateway only), LinkedIn (`linkedin-api-client`), SendGrid (`@sendgrid/mail` + `@sendgrid/client`). Plus generic protocol nodes not tied to one vendor: `http.ts`, `soap.ts`, `sftp.ts`, `odata.ts`, `xml.ts`, `csv.ts`.

**Twilio is the one exception to the "Runtime logic" row**: `TwilioManager` (`packages/core/src/lib/twilioManager.ts`) resolves its own credential straight from the database (via `getDatabaseManager()`/`resolveAllCredentials`, the same lookup `ctx.getCredential` wraps) instead of taking an already-resolved credential, so there is no `functionLibraryTwilio.ts` — `nodes/twilio.ts`'s `execute()` and `compileExecute()` both call the exact same `TwilioManager.<op>(credentialName, ...)` static methods. Because that pulls `DatabaseManager.ts` (and transitively `better-sqlite3`, `node:fs`, `node:crypto`) into a file that's still statically imported client-side for the node menu, `execute()` loads it with a `webpackIgnore`/`turbopackIgnore`-annotated `import()` instead of a top-level import — see `nodes/twilio.ts`'s `loadTwilioManager` and [architecture.md](./architecture.md)'s "Where node code actually runs". Don't reach for this pattern by default: it only exists because Twilio's credential is a single static Basic-Auth pair simple enough to fold into the manager; the ctx/functionLibrary split below is still the default for a new integration.

## Adding a new integration

1. Add the credential type (fields it needs) to `packages/shared/src/registry.ts` + a `CredentialTypeId` variant and data shape in `packages/shared/src/types.ts`.
2. Add `packages/core/src/lib/<provider>Manager.ts` wrapping the provider's SDK, with a `forAuth`/`forCredential` cache (see the table above).
3. Add `packages/core/src/server/functionLibrary<Provider>.ts` with the actual node execution functions, reading credentials via `credentialEnv.ts` conventions for the deployed-script path (see [auth.md](./auth.md)), then calling into the manager from step 2.
4. Add `packages/graph/src/nodes/<provider>.ts` with editor-only pin definitions and, for every operation, both an `execute()` (resolves the credential from the vault via `ctx.getCredential`, calls the manager) and a `compileExecute()` (calls the matching `functionLibrary<Provider>.ts` export) — see `jira.ts`/`dropbox.ts`. Register it in `src/graph/nodes/index.ts` (`import "@hermione/graph/nodes/<provider>";`).
5. Add struct/enum files under `packages/graph/src/structs/` / `packages/graph/src/enum/` only if the provider needs custom typed pin shapes.
6. If the provider's SDK entry point unconditionally `require`s Node built-ins at module scope (check by grepping the SDK's main file), add a browser stub — see "Browser-side SDK stubs" below.

## Browser-side SDK stubs

Some provider SDKs (`googleapis`, `facebook-nodejs-business-sdk`, `mongodb`, `@slack/web-api`) unconditionally `require` Node built-ins at their entry point's module scope and would break the browser bundle if imported by editor code — even though the actual `execute()` calls that use them only ever run server-side (see [architecture.md](./architecture.md)). `packages/core/src/lib/googleapisBrowserStub.ts`, `facebookSdkBrowserStub.ts`, `mongoBrowserStub.ts`, and `slackSdkBrowserStub.ts` exist to satisfy the import client-side (aliased in `next.config.mjs`'s `turbopack.resolveAlias`) — they just throw if actually called, which never happens in the browser. Providers whose SDK doesn't do this (e.g. `jira.js`, the Dropbox SDK) can be imported directly into `nodes/<provider>.ts` with no stub needed. Twilio uses a third option instead of a stub — see the note above the "Adding a new integration" list.
